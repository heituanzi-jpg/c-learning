# 论文急救路径：P0 → P3（从"什么都不会"到 Mode A 基线）

> **用法（和 C 语言讲义同一套规矩）**
>
> 通关四步：**读 → 敲 → 练 → 考**。代码手敲，命令可复制。
> **这条线和 C 语言并行，不是排队。** 每天 4 小时预算：C 语言吃 2~3h，本路径吃 1~2h，到点就停，做不完顺延。
> 状态差的日子，两条线共用一个最低剂量：**打开终端看一眼代码，就算今天没断。**

## P0 · 心理建设（1 天，30 分钟）

**目标**：消除"我什么都不会"的恐惧。这个阶段不学任何东西。

**为什么要先做这一步**：你对论文的恐惧不是能力问题，是"没见过"问题。治疗方法只有一种：隔着安全距离看一眼，发现对方也是普通人写的东西。

**任务（只做三步，做完就收工）**：

1. 打开 GitHub，搜索 `VulTrial` 或 `GPTLens`（LLM 代码安全审查方向的论文仓库）
2. 点进仓库，把 README 从头滚到尾。**不要求看懂**——看到不懂的词，心里默念一句"哦，有这么个词"，继续滚
3. 关掉页面，结束。今天论文线任务完成

✅ **验收**：无交付物。接触即胜利。

⚠️ **唯一禁令**：不许点开代码文件细看，不许查不懂的术语。今天的剂量就是"看一眼"，多看一口都会触发"我不行"的旧模式。

## P1 · Python 急救（5 天，每天 1 小时）

**目标**：能写一个 50 行的 Python 脚本：读一段代码 → 发给 DeepSeek API → 把回复存进文件。

**为什么学 Python 而且是"急救"学法**：论文实验代码全是 Python。但你不需要"学 Python"，你只需要**五个零件**，够拼出实验脚本就行。面向对象、装饰器、多线程——统统不学，那是以后的事。

**前置条件**：Ubuntu 终端（python3 系统自带，先跑 `python3 --version` 确认看到版本号）；建好论文基地：

```bash
mkdir -p ~/code/paper && cd ~/code/paper
```

### D1 · 变量、字符串、print

**是什么**：和 C 语言的变量一个道理——贴标签的储物柜，只是不用声明类型。

【动手】新建 `d1.py`（`touch d1.py`，VS Code 打开），手敲：

```python
name = "论文"
day = 1
print("Hello", name)
print("第", day, "天")
```

运行：`python3 d1.py`

✅ 看到两行输出。对比 C 语言记一条笔记：Python 没有分号、没有 `int`、没有花括号。

⚠️ 常见错误：把 C 的习惯带进来写了分号——Python 不报错，但别养这个习惯。

### D2 · 列表、字典、for 循环

**是什么**：列表 = 一排编了号的储物柜；字典 = 贴了名字的储物柜（按名字取，不按号码）。

【动手】`d2.py`：

```python
files = ["main.c", "utils.c", "test.c"]

for f in files:
    print("发现代码文件:", f)

info = {"name": "main.c", "lines": 42}
print(info["name"], "有", info["lines"], "行")
```

✅ 看到三行"发现代码文件"加一行统计。

⚠️ 常见错误：for 循环体忘记缩进——**Python 用缩进代替花括号**，缩进错 = 结构错。这是 Python 第一坑，记进 mistakes.md。

### D3 · 函数、读文件

**是什么**：函数和 C 语言一样——把一段活儿打包起个名字。读文件 = 让程序打开一个文本文件，把内容装进变量。

【动手】先在终端造一个测试文件：`echo "int main() { return 0; }" > sample.c`，然后 `d3.py`：

```python
def read_code(filename):
    with open(filename, "r") as f:
        content = f.read()
    return content

code = read_code("sample.c")
print("读到了", len(code), "个字符")
print(code)
```

✅ 看到字符数和那行 C 代码。

⚠️ 常见错误：`FileNotFoundError`——文件名写错或不在当前目录，先 `ls` 确认文件在不在。

### D4 · requests 库调 API

**是什么**：API = 餐厅的点餐窗口。你的程序递一张单子（请求）进去，厨房（DeepSeek 的服务器）做好菜（回复）递出来。`requests` 就是递单子的工具。

**前置**：装库 `pip install requests`（报权限错就用 `pip install --user requests`）；需要 DeepSeek API Key——还没注册的话今天先注册（platform.deepseek.com），这本来就是 7 月任务清单里的。

⚠️ **API Key 安全铁律（现在就记进 mistakes.md 预防）**：Key **绝不写进代码**，写进环境变量：

```bash
export DEEPSEEK_API_KEY="你的key"
```

【动手】`d4.py`：

```python
import os
import requests

key = os.environ["DEEPSEEK_API_KEY"]
url = "https://api.deepseek.com/chat/completions"
headers = {"Authorization": "Bearer " + key}
data = {
    "model": "deepseek-chat",
    "messages": [{"role": "user", "content": "用一句话说：什么是缓冲区溢出？"}]
}

resp = requests.post(url, headers=headers, json=data)
print(resp.json()["choices"][0]["message"]["content"])
```

✅ 看到 DeepSeek 的回答打印出来。**这一刻你已经会"程序调大模型"了——你论文的全部实验，底层就是这一个动作。**

⚠️ 常见错误：`KeyError` 或 401 → 环境变量没设或 key 错了，`echo $DEEPSEEK_API_KEY` 检查；超时/网络错 → 检查科学上网或换时间重试。

### D5 · 整合：能跑的实验脚本

**目标**：把 D1–D4 拼成一个完整脚本——**这就是你论文实验的雏形**。

【动手】`d5.py`：

```python
import os
import requests

def read_code(filename):
    with open(filename, "r") as f:
        return f.read()

def ask_ai(code):
    key = os.environ["DEEPSEEK_API_KEY"]
    url = "https://api.deepseek.com/chat/completions"
    headers = {"Authorization": "Bearer " + key}
    data = {
        "model": "deepseek-chat",
        "messages": [{"role": "user", "content":
            "你是代码安全审查员。找出这段代码的安全问题，用中文简短回答：\n" + code}]
    }
    resp = requests.post(url, headers=headers, json=data)
    return resp.json()["choices"][0]["message"]["content"]

code = read_code("sample.c")
result = ask_ai(code)

with open("result.txt", "w") as f:
    f.write(result)

print("审查完成，结果已存入 result.txt")
```

✅ **P1 通关验收**：`python3 d5.py` 跑完，`cat result.txt` 能看到 AI 对 sample.c 的审查意见。

**顺手把 sample.c 改成一段有 strcpy 的 C 代码再跑一遍**——看到 AI 报出"缓冲区溢出"时，你会第一次感到"我的论文不是天书"。

## P2 · 跑通别人的论文代码（1–2 周，每天 2 小时）

**目标**：把一篇开源论文的代码在你电脑上跑起来，看到输出。**这阶段的规矩：不求看懂，只求能跑。**

**为什么**：看懂一篇论文的代码要三个月，跑通只要一周。先跑通，你就有了"能出结果的实验台"，P3 的魔改才有地方下手。

### 第 1 步：选仓库（Day 1，最重要的一步）

标准（五条全占才选）：

| 标准 | 为什么 |
|---|---|
| 主题对口：LLM + 代码安全/漏洞检测 | 你的 Mode A 要在它基础上改 |
| 有 README 且写了怎么跑 | 没有说明书的不碰 |
| 有 requirements.txt 或环境说明 | 依赖不明的坑最深 |
| 近一年有更新 | 死仓库的依赖多半已过期 |
| Stars 较多 / 有对应论文 | 群众帮你验过货 |

让 Kimi（手机版/网页版）帮你搜："找 3 个 LLM 代码安全审查方向、有开源代码的论文仓库，要 README 完整的"，然后你按上表挑一个。

### 第 2 步：克隆 + 装环境（Day 2）

```bash
cd ~/code/paper
git clone 仓库地址
cd 仓库名
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
```

📖 新词：`venv` = 虚拟环境，给这个项目单独隔一间"厨房"，装的调料不污染别的项目。每次回来干活先 `source venv/bin/activate` 进厨房。

### 第 3 步：跑（Day 3 起）

按 README 跑它的主程序（通常是 `python main.py` 或类似）。然后进入本阶段的主循环：

```
跑 → 报错 → 复制报错全文 → 问 AI → 按提示改 → 再跑
```

**报错求救咒语（论文线专用）**：

> 我是零基础研一新生，在 Ubuntu 上跑一个开源论文的代码。这条命令：【命令】报这个错：【报错全文】。请用大白话告诉我最可能的原因和**下一步该敲什么命令**，只给一步，不要全堆给我。

### 第 4 步：可能要 API Key

这类仓库大多要 OpenAI/DeepSeek 的 Key，写在它的配置文件或环境变量里（README 会写）。沿用 D4 的安全铁律。

✅ **P2 通关验收**：程序跑完，输出目录里出现了结果文件。**这一天值得在子弹笔记上画个圈。**

⚠️ 常见错误：

| 症状 | 大概率原因 | 怎么办 |
|---|---|---|
| `No module named 'xxx'` | 依赖没装全 / 没进 venv | 先 `source venv/bin/activate`，再 `pip install xxx` |
| Python 版本报错 | 仓库要 3.10 你的是别的版本 | 报错全文发我，个案处理 |
| API 报错 401/余额不足 | Key 没配或没充值 | 查环境变量；DeepSeek 充值几块钱就够跑很久 |
| 跑一半卡死没输出 | 在等 API 响应，正常的 | 等 1–2 分钟；超过 5 分钟 Ctrl+C 再问 |

## P3 · 论文 Mode A 基线（2–3 周，每天 2 小时）

**目标**：从"能跑别人的"变成"跑出自己的"——理解结构、改 prompt、换自己的数据、记录结果。

### P3-1 · 读 Methodology，对照代码找对应（约 3 天）

- 打开论文 PDF 的 Methodology 一节，同时打开代码主文件
- 玩一个"对号入座"游戏：论文里写的每个模块（每个 agent、每个步骤），在代码里找到对应的函数/文件，在代码上面写一行注释 `# 这就是论文里的"检测Agent"`
- 不要求懂每一行，能对上 70% 就算过

✅ 验收：能指着代码说"这块是论文第 X 节说的那个东西"。

### P3-2 · 改一个 agent 的 prompt，看结果变化（约 3 天）

- 在代码里找到 prompt 所在的字符串（搜 `"You are"` 或 `"你是"` 通常能找到）
- 改一句：比如让审查员"更严格，可疑的都报"
- 用仓库自带的同一个测试用例，改前跑一遍存结果，改后跑一遍存结果
- 对比两份输出，把差异写进 experiments.md

✅ 验收：你能说出"改了哪句 prompt，输出从什么变成了什么"。**这就是"做实验"的本质——改一个变量，看结果变化。**

### P3-3 · 换一段自己的测试代码，跑一轮审查（约 3 天）

- 从你自己的 C 语言练习里挑一段（比如故意写个有 `strcpy` 的小程序）
- 喂给系统，跑完整流程，拿到审查结果
- 人工核对：它报的对不对？漏了什么？多报了吗？

✅ 验收：结果 + 你的人工核对意见，一起记进 experiments.md。

### P3-4 · 记录 Mode A 基线（约 2 天）

把 P3-2 和 P3-3 的结果整理成一条完整的实验记录：

```
Mode A 基线 = 原论文配置 + 原 prompt + 我的测试数据 → 得到的结果
```

**这条记录就是你 8 月月度任务的交付物，也是后续所有实验（Mode B/C/D）的对照组。**

✅ **P3 通关验收（= 第二阶段毕业）**：experiments.md 里有一条完整的 Mode A 基线记录，含：配置、数据、结果、人工核对意见。

## 本路径避坑大全（卡住了先翻这页）

| # | 症状 | 病因 | 解法 |
|---|---|---|---|
| 1 | 点开论文仓库看了一圈，觉得"我不行" | 剂量超标 | 回到 P0 规矩：只看 README，看完就关 |
| 2 | Python 报错缩进相关 | 把 C 的花括号习惯带来了 | Python 靠缩进，对齐同一块 |
| 3 | `FileNotFoundError` | 文件不在当前目录 | `pwd` + `ls` 确认位置 |
| 4 | 调 API 报 KeyError/401 | 环境变量没设或 key 错 | `echo $DEEPSEEK_API_KEY` 检查 |
| 5 | 把 API Key 写进了代码文件 | 违反安全铁律 | 立刻改成环境变量；已传 GitHub 的话找龙虾注销重置 |
| 6 | `No module named` | 没进 venv 或依赖没装 | activate → pip install |
| 7 | 对着报错改了 2 小时还没好 | 陷进去了 | 停下来，报错全文发龙虾/舵手，求助不丢人 |
| 8 | 想看懂仓库每一行代码才开始改 | 完美主义陷阱 | P2 的规矩：能跑就行；P3 只需要懂结构 |
