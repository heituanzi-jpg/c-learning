# CS 第一阶段操作手册：从零基础到「Hello, 408!」

> **导师的话**
> 这份手册是你第一阶段（大一上 · 编程入门）的"操作说明书"。
> 使用方法只有一句话：**边看边做，做一步，勾一步。**
> 遇到任何一步，屏幕上出现的内容和手册写的不一样——停下来，把屏幕上的字原样发给我，不要自己瞎试。

## 第 0 章 使用说明（2 分钟读完）

### 0.1 符号约定

| 样子 | 含义 |
|---|---|
| `灰色底文字` | 要在终端（黑窗口）里输入的命令，或在键盘上按的键 |
| 【方括号】 | 软件界面上要点的按钮 |
| ⚠️ | 易错点，看到这里放慢 |
| ✅ | 做完这步应该看到的结果，看到了才算过 |

### 0.2 两条铁律

1. **命令可以复制粘贴**（本手册里的命令随便抄），**但代码必须一个字符一个字符手敲**。手感就是这么来的，复制代码 = 没学。
2. **报错不是失败，是电脑在跟你说话。** 看到满屏红字不要慌，它的第一行通常在告诉你哪一行出了问题。

### 0.3 每天学习的"三件套"

每天开始学习前，打开这三样东西，摆好再开始：

1. **Ubuntu 终端**（黑窗口，运行代码的地方）
2. **VS Code**（写代码、写笔记的地方）
3. **本周的笔记文件**（第 3 章会教你建好它）

## 第 1 章 环境配置（只做一次，约 1~1.5 小时）

> 本章目标：在你的电脑上装好"写 C 语言 → 运行 C 语言"的完整流水线，最后看到屏幕打出 `Hello, 408!`。

### 1.1 打开你的 Ubuntu

1. 按一下键盘上的 **Windows 键**
2. 直接打字输入：`ubuntu`
3. 在搜索结果里点【Ubuntu】（一个橙紫色图标）
4. 弹出一个黑色窗口——这就是**终端**，你今后的主战场
5. 在任务栏（屏幕最下面）找到它的图标，**右键 →【固定到任务栏】**，以后点一下就开

**认识这个黑窗口：**

你会看到类似这样的一行字：

```
yourname@DESKTOP-XXXX:~$
```

- `yourname` = 你的用户名
- `~` = 你的"家目录"，就是 `/home/你的用户名`，可以理解成"我的文档"
- `$` 后面闪烁的方块 = **光标**，你打的东西会从这里出现
- 这一整行叫"提示符"，意思是："我在等命令"

### 1.2 终端的三个生存技巧（先学会，保命用）

| 技巧 | 操作 | 什么时候用 |
|---|---|---|
| **粘贴** | 复制命令后，在黑窗口里点**鼠标右键**（或按 `Ctrl+Shift+V`） | ⚠️ 终端里 `Ctrl+V` 不管用！ |
| **紧急停止** | `Ctrl + C` | 程序卡死、疯狂刷屏、输错东西时，按它 = "停下" |
| **调出上一条命令** | 按 `↑` 方向键 | 不用重复打字 |

### 1.3 安装 gcc 和 git（编译器 + 版本管理工具）

在黑窗口里粘贴这一整行，然后回车：

```bash
sudo apt update && sudo apt install -y gcc git
```

⚠️ **会出现 `[sudo] password for 你的用户名:`，让你输密码。注意：你打字的时候屏幕不会有任何反应——没有星号、没有圆点，这是 Linux 几十年的传统，不是卡了！** 盲打完密码，直接回车。

- 接下来屏幕会刷很多字，等 1~5 分钟（取决于网速）
- ✅ 最后重新出现 `~$` 提示符，没有大片红色 `Err` 字样 = 成功

**验证安装成功（逐个输入，回车）：**

```bash
gcc --version
```

✅ 看到类似 `gcc (Ubuntu 11.x.x-...) 11.x.x` 的字样 = gcc 装好了。

```bash
git --version
```

✅ 看到类似 `git version 2.x.x` = git 装好了。

> 📖 **术语时间**（顺手记进你未来的术语词典）：
> - **gcc** = 编译器，把你能看懂的 C 代码"翻译"成电脑能执行的文件的软件。
> - **git** = 代码的"时光机 + 云备份"，第 7 周正式学它。
> - **sudo** = "以管理员身份执行"，相当于 Windows 的"右键→以管理员身份运行"。
> - **apt** = Ubuntu 的"应用商店"，装软件就用它。

### 1.4 给代码建一个家

粘贴，回车：

```bash
mkdir ~/code
```

再粘贴，回车：

```bash
cd ~/code
```

- `mkdir` = 建文件夹（make directory）
- `~/code` = 你家目录下的 code 文件夹
- `cd` = 进入这个文件夹（change directory）

✅ 提示符从 `~$` 变成 `~/code$`，说明你进来了。

> **从此以后，你所有的代码和笔记，全部住在 `~/code` 里面。** 不放在桌面、不放在微信文件夹——程序员的东西要集中。

### 1.5 安装 VS Code（写代码的编辑器）

1. Windows 下打开浏览器，访问官网：**code.visualstudio.com**
2. 点【Download for Windows】，下载后双击安装包
3. 安装过程一路【下一步】，⚠️ **到"选择附加任务"那一页时，把所有勾都勾上**（尤其是"添加到 PATH"）
4. 装完打开 VS Code
5. 装两个插件（点左边栏那个**四个方块的图标**（扩展），在搜索框输入名字，点【Install】）：
   - **WSL**（微软 Microsoft 出品，图标是蓝绿色的 >< ）——必装，它让 VS Code 能操作 Ubuntu 里的文件
   - **Chinese (Simplified)**（简体中文语言包）——可选，装完界面变中文

### 1.6 让 VS Code 住进 Ubuntu

回到黑窗口，确认提示符是 `~/code$`（如果不是，输入 `cd ~/code` 回车），然后输入：

```bash
code .
```

（注意 `code` 后面有个空格和一个点，这个点 = "当前文件夹"）

- 第一次运行会自动安装 VS Code Server，等 1~2 分钟
- VS Code 弹出来，看**左下角**：出现绿色小标志，写着 `WSL: Ubuntu`
- ✅ 看到这个绿标 = 成功。从此你在 VS Code 里写的就是 Linux 里的文件，改的就是真东西

### 1.7 人生第一个程序

**第 1 步：新建文件。**
在黑窗口输入（这样最快）：

```bash
touch hello.c
```

- `touch` = 建一个空文件
- ✅ 看 VS Code 左边的文件列表（Explorer），出现了 `hello.c`，双击它打开

**第 2 步：手敲代码。**
在右边编辑区，**一个字符一个字符手敲**（不许复制）：

```c
#include <stdio.h>

int main() {
    printf("Hello, 408!\n");
    return 0;
}
```

敲的时候注意：
- 所有标点都是**英文标点**（`;` 不是 `；`，`"` 不是 `"`）
- 大小写要一模一样，`#include` 前面不要有空格
- VS Code 会自动补括号，别敲重复了

**第 3 步：保存。**
按 `Ctrl + S`。
⚠️ **新手第一大坑：改了代码没保存，结果运行的还是旧代码。** 文件名旁边出现圆点 ● = 没保存；变成 × = 已保存。

**第 4 步：编译运行。**
回到黑窗口，粘贴，回车：

```bash
gcc hello.c -o hello && ./hello
```

✅ 屏幕打出一行 `Hello, 408!` —— 🎉 **点火成功！截图发给我或者自己存好，这是你程序员生涯的第一张照片。**

### 1.8 这条命令是什么意思？（拆开看，不用背）

```
gcc hello.c -o hello  &&  ./hello
└─┬─┘ └──┬──┘ └─┬──┘    │   └──┬──┘
  │      │      │       │      └── 运行当前文件夹里的 hello 程序
  │      │      │       └───────── 前面成功了，才执行后面
  │      │      └───────────────── 翻译出来的成品取名叫 hello（-o = output）
  │      └──────────────────────── 你写的源代码文件
  └─────────────────────────────── 翻译官 gcc 出场
```

**生活类比：** `hello.c` 是你写的中文信，`gcc` 是翻译官，`hello` 是翻译好的英文信，`./hello` 是把信寄出去让对方读。

### 1.9 本章报错自查表

| 屏幕上出现 | 什么意思 | 怎么办 |
|---|---|---|
| `gcc: command not found` | gcc 没装上 | 回到 1.3 重新执行 |
| `code: command not found` | VS Code 没装好或没勾 PATH | 回到 1.5，重装并勾全附加任务 |
| 代码编译报一堆错，行号处有 `；` | 用了中文分号 | 换成英文 `;`，`Ctrl+S`，重新编译 |
| 改了代码，运行结果没变 | 没保存 | `Ctrl + S` 后重新编译运行 |
| `Permission denied` | 权限不够 | 命令最前面加 `sudo ` 再试 |
| `code .` 打开了，但左下角不是绿色 WSL 标志 | WSL 扩展没装 | 回到 1.5 第 5 步 |

### 1.10 🎁 加餐（可选，做了会有顿悟感）：ssh 进你的 MT6000 看一眼

你折腾过的 MT6000 路由器，里面跑的是 OpenWrt——**它就是一个 Linux**。现在你已经会终端了，可以进去看看：

```bash
ssh root@192.168.8.1
```

- 问你 `Are you sure you want to continue connecting?` → 输入 `yes` 回车
- 输入你路由器后台的管理密码（同样是盲打不显示）
- 进去后试试这两条：

```bash
cat /etc/openwrt_release
```

✅ 看到它的系统版本信息。

```bash
ls
```

✅ 看到一排文件夹——和你 Ubuntu 里的味道一模一样。

**这一刻请停三秒，体会一下：你的路由器就是一台 Linux 电脑，终端是通往所有设备的门。** 科班生大一才悟到的事，你第一周就摸到了。

输入 `exit` 回车，退出路由器，回到自己的电脑。

## 第 2 章 终端生存 20 命令（第 1~2 周边用边会，不用背）

> 学法和英语单词一样：不是背下来的，是用熟的。每天照着"微练习"敲一遍，两周后你闭着眼都会。

| # | 命令 | 一句话作用 | 微练习（照做一遍） |
|---|---|---|---|
| 1 | `pwd` | 我在哪？（显示当前位置） | 输入 `pwd` 回车 |
| 2 | `ls` | 看看当前文件夹里有啥 | 输入 `ls` 回车 |
| 3 | `cd 文件夹名` | 进入某文件夹 | `cd ~/code` |
| 4 | `cd ..` | 回上一层 | `cd ..` 然后 `pwd` 看变化 |
| 5 | `mkdir 名字` | 建文件夹 | `mkdir test1` |
| 6 | `touch 名字` | 建空文件 | `touch a.txt` |
| 7 | `cat 文件名` | 把文件内容打印到屏幕 | `cat hello.c` |
| 8 | `cp 甲 乙` | 复制 | `cp a.txt b.txt` 然后 `ls` 检查 |
| 9 | `mv 甲 乙` | 移动 / 改名 | `mv b.txt c.txt` |
| 10 | `rm 文件名` | ⚠️ 永久删除（**不进回收站！**） | `rm c.txt` |
| 11 | `rm -r 文件夹名` | ⚠️ 删除整个文件夹（**用前想三秒**） | `rm -r test1` |
| 12 | `clear` | 清屏 | 屏幕乱了就用 |
| 13 | `history` | 看我敲过哪些命令 | 输错命令时翻案底用 |
| 14 | `↑` 键 | 调出上一条命令 | 连按可一直往前翻 |
| 15 | `gcc 源文件 -o 名字` | 编译 C 程序 | `gcc hello.c -o hello` |
| 16 | `./程序名` | 运行当前文件夹的程序 | `./hello` |
| 17 | `sudo 命令` | 用管理员权限执行 | `sudo apt update` |
| 18 | `code .` | 用 VS Code 打开当前文件夹 | 每天开工第一件事 |
| 19 | `ssh 用户@地址` | 远程进入另一台设备 | `ssh root@192.168.8.1` |
| 20 | `exit` | 退出（ssh 会话 / 关闭终端） | 每天收工最后一件事 |

⚠️ **关于 `rm` 的特别警告：** 终端里删除 = 永久消失，没有回收站，没有后悔药。规矩：**输完 `rm` 命令后，手指放在回车键上停三秒，确认路径没写错，再按。**

**组合拳示例（看懂即可）：**

```bash
mkdir ~/code/c-learning && cd ~/code/c-learning && mkdir week01 && cd week01 && touch test.c && ls
```

这一串 = 建文件夹 → 进去 → 再建 → 再进 → 建文件 → 看看成果。`&&` 就是"然后"。

## 第 3 章 程序员的笔记法（重点章）

> 你说你不会做笔记——没关系，因为**程序员记笔记的方法和学校里的完全不一样**。学校里那套（抄板书、抄定义、画满荧光笔）在编程里没用。这一章教你一套"三个本子"系统，照做就行，不需要任何天赋。

### 3.1 先纠正观念：笔记 = 给三个月后的自己留的救命纸条

记住一个事实：**三个月后的你，会把你今天学的东西忘得一干二净。** 那时你就是一个陌生人。

所以笔记只有两个标准：

1. **三个月后的你能看懂**（用大白话写，别抄书上的术语解释）
2. **能复制粘贴直接用**（代码、命令，原样能跑）

❌ 错误示范：把视频里的定义原封不动抄一遍（"指针是存储内存地址的变量"——抄完你也不懂，三个月后更不懂）

✅ 正确示范：**一段能跑的代码 + 一句你自己的大白话**

### 3.2 工具：VS Code + Markdown（.md 文件）

**为什么不用 Word、不用纸质本？**

- 代码贴进去格式全乱，还没法搜索
- 以后你的笔记要传上 GitHub（第 7 周），程序员的世界通用笔记格式就是 Markdown

**Markdown 是什么？** 一种"用几个符号排版"的纯文本写法。你只需要会 5 个符号：

| 你输入的 | 显示效果 |
|---|---|
| `# 标题` | 大标题 |
| `## 小标题` | 小一级的标题 |
| `- 一条` | 一个列表点 |
| `**重点**` | **加粗** |
| 三个反引号 ` ``` ` 把代码包起来 | 代码块（像本手册这样） |

**现在就把笔记系统建好（一次性，黑窗口里逐行复制执行）：**

```bash
mkdir -p ~/code/notes
mkdir -p ~/code/c-learning/week01
cd ~/code/notes
touch glossary.md
touch mistakes.md
touch week01.md
ls
```

✅ 最后一行 `ls` 应该显示：`glossary.md  mistakes.md  week01.md`

**你的文件体系（以后都照这个命名，全部英文小写，省得切输入法）：**

```
~/code/
├── notes/                  ← 笔记之家
│   ├── glossary.md         ← 本子一：术语词典
│   ├── mistakes.md         ← 本子二：错题/报错本
│   ├── week01.md           ← 本子三：每周笔记（每周一个文件）
│   ├── week02.md（第2周再建）
│   └── ...
└── c-learning/             ← 代码之家
    ├── week01/             ← 第1周写的所有 .c 文件
    │   └── hello.c
    ├── week02/（第2周再建）
    └── ...
```

在 VS Code 左边文件列表里双击任意 `.md` 文件就能打开写。写 .md 时按 `Ctrl+Shift+V` 可以预览排版效果（可选）。

### 3.3 三个本子，各记什么（核心！）

#### 📕 本子一：术语词典 `glossary.md`

**什么时候记：** 看视频/看书时，遇到任何听不懂的词——编译器、指针、内核、内存、进程、数组……**立刻暂停，记一条**。

**格式（每条三行）：**

```markdown
## 编译器
- 大白话：翻译官。把我写的 C 代码翻译成电脑能执行的文件。我用的这个叫 gcc。
- 出处：翁恺第1章 / 手册1.8
- 状态：✅ 懂了
```

**要点：** "大白话"一栏必须**用你自己的话**，哪怕不严谨。写"翻译官"比抄"将高级语言转换为机器语言的程序"强一百倍。状态栏诚实点：✅ 懂了 / ❓ 还晕（❓ 的攒着来问我）。

#### 📗 本子二：错题/报错本 `mistakes.md`

**什么时候记：** 每次程序报错、结果不对、被卡住超过 10 分钟——**解决之后立刻记一条**。

**格式（每条四行）：**

```markdown
## 2026-07-29 报错：expected ';' before 'return'
- 我写的：printf("Hello") 后面没打分号
- 原因：C 语言每句话结尾必须有英文分号 ;
- 解法：补上分号，重新 gcc 编译就过了
- 教训：报错信息第一行有行号，先看那一行
```

**这本子是你最宝贵的财富。** 每个程序员都有一本看不见的错题本，你只是把它写下来而已。半年后翻一翻，你会笑出声，也会发现自己踩的坑越来越高级——这就是成长本身。以后面试能聊、写博客能用、考研复试都是素材。

#### 📘 本子三：每周笔记 `week01.md`、`week02.md`……

**什么时候记：** 每天学习结束时，花 5 分钟填一次。

**格式（固定模板，附录 A 有可以直接复制的完整版）：**

```markdown
# 第 1 周 · 终端与环境

## 7-29（周二）用时：1.5h
### 今天学了什么（3行以内，自己的话）
- 装好了 gcc 和 git，知道了终端就是跟电脑打字聊天
- 写出了第一个程序 hello.c
### 今天写的代码
- `~/code/c-learning/week01/hello.c`（能跑）
### 卡住的地方 + 怎么解决的
- sudo 输密码屏幕没反应，以为坏了 → 查了手册，原来是正常设计
### 还没懂的（攒着问导师）
- gcc 后面的 -o 到底是什么的缩写？（哦手册写了，output）✅
```

### 3.4 看一节课的标准动作（SOP，建议打印贴墙上）

每次看翁恺/黑马的课，严格按这个流程走，**一步都不许跳**：

```
① 打开三件套：终端 + VS Code + 今天的 week0X.md
② 看视频（关掉弹幕，倍速最高 1.25）
③ 老师每写一个程序 → 暂停 → 自己手敲一遍 → 编译 → 跑通
④ 跑不通 → 先自己看报错第一行 → 解决了 → 记进 mistakes.md
⑤ 看完一集 → 在 week0X.md 写"一句话总结"（不超过两行）
⑥ 遇到新术语 → 记进 glossary.md
⑦ 一天结束 → 合上电脑 → 在你的子弹笔记上打勾 ✅
```

⚠️ 第 ③ 步是分水岭。**"看懂了"和"会写了"之间隔着一万次手敲。** 只看不敲 = 白看，这是无数人用半年时间验证过的真理。

### 3.5 笔记示范：一份"及格"的笔记长什么样

### 3.6 笔记的量：每天 5~10 分钟封顶

- 笔记写多了是负担，写少了等于没学。按上面的 SOP 走完，自然就是 5~10 分钟。
- **宁可只写三行，不能一天不写。** 断了就接不上，接不上就想放弃——这是你这种性格最大的风险点，用最小的量维持连续性。

### 3.7 📒 本子四（论文线专用）：实验记录 `experiments.md`

> 启动时间：论文急救路径 P1 开始那天。它和三个本子是平行关系——三个本子管"学 C 语言"，这一本管"做论文实验"。

**什么时候记：** 每跑一次实验（调一次 API、跑一轮仓库代码、改一次 prompt 看变化），**当天记一条**。记不住 = 白跑。

**先建文件：**

```bash
cd ~/code/notes && touch experiments.md
```

**格式（每条六行）：**

```markdown
## 2026-08-12 实验：D5脚本首跑
- 目的：验证"读代码→调API→存结果"流程能跑通
- 环境：Ubuntu / python3.12 / deepseek-chat
- 改动：无（首次跑通）
- 结果：result.txt 生成了 3 条审查意见，其中"缓冲区溢出"报对了
- 结论：流程通了；AI 对 strcpy 敏感，对数组越界没报
- 下一步：换一段有数组越界的代码再测
```

**三条铁律：**

1. **环境必记**。模型版本、依赖版本不同，结果就不同。三个月后复现不出结果，90% 是因为当时没记环境。
2. **改动只改一个**。一次改多个变量，结果变了你都不知道是谁的功劳——这是实验方法的第一课。
3. **失败也记**。"改了 X，结果反而变差"和成功的记录一样值钱，写论文时这些都是素材。

**Mode A 基线的记录**：跑到 P3-4 时，把基线记录用 `## Mode A 基线（定稿）` 作为标题记一条完整版——它是后续所有实验的对照组，也是论文实验章节的第一块砖。

**API Key 安全（再说一遍，因为这本子里最容易出事）：** Key 只住环境变量（`export DEEPSEEK_API_KEY=...`），绝不写进任何 `.py` / `.md` 文件，绝不上传 GitHub。万一泄了，立刻去平台后台注销重置，然后来找我。

## 第 5 章 FAQ 急救箱

**Q1：Ubuntu 密码忘了怎么办？**
别慌，来找我，重置密码有一条专门的命令，我到时候手把手带你。

**Q2：终端字太小看不清？**
按住 `Ctrl` 滚动鼠标滚轮；或在窗口标题栏右键 →【属性】里调字体大小。

**Q3：我在 Windows 里能找到 Ubuntu 的文件吗？**
能。打开 Windows 资源管理器，在地址栏输入 `\\wsl$` 回车，就能看到 Ubuntu 的整个文件系统，你的代码在 `Ubuntu → home → 你的用户名 → code` 里。⚠️ 但平时别从 Windows 这边改文件，养成在 VS Code（WSL 模式）里操作的习惯。

**Q4：`apt` 下载特别慢？**
可能是软件源在国外。跟我说一声"源太慢"，我给你换国内镜像源的命令（一条，复制粘贴就行）。

**Q5：不小心把终端关了 / 电脑重启了，东西还在吗？**
全都在。文件都存在硬盘里，重新打开终端，`cd ~/code` 回家，继续。

**Q6：想删掉某个练废的文件夹？**
`rm -r 文件夹名`。再看一遍第 2 章的红色警告：删了就永远没了，确认三秒再回车。

**Q7：VS Code 左下角没有绿色 WSL 标志了？**
关掉 VS Code，回到终端，在 `~/code` 下重新输入 `code .`。

**Q8：我能用 AI（比如 Kimi）帮我写代码吗？**
能问，不能代写。第一阶段你在长肌肉，让 AI 代写 = 请别人替你健身。正确用法见**第 6 章**：把 Kimi Code 装进终端，当"教练"用——问报错、问概念、让它出题考你，但代码必须自己敲。

## 第 6 章 AI 学习伙伴：Kimi Code（终端里的私人教练）

> 这一章教你把 AI 装进终端：出错了，现场有人救。**但先立规矩——在第一、二阶段，它是你的"教练"，不是"代写"。教练让你变强，代写让你变废。**

### 6.1 它是什么（大白话）

- **Kimi Code** 是一个住在终端里的 AI 助手：在黑窗口里输入 `kimi`，就能直接用大白话和它对话。
- 它和网页版 Kimi 最大的区别：**它能看见你启动时所在文件夹里的文件**，也能在你同意后运行命令。报错不用复制粘贴，它自己能去看。
- 类比：网页版 Kimi 是"电话那头的家教"，终端里的 Kimi Code 是"坐在你旁边、能看到你屏幕的家教"。

### 6.2 安装（只做一次，约 5 分钟）

**第 1 步：** 打开 Ubuntu 终端，粘贴，回车：

```bash
curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash
```

**第 2 步：** 装完后关闭终端重新打开（让系统认到新命令）。不想重开就粘贴：

```bash
source ~/.bashrc
```

**第 3 步：** 验证：

```bash
kimi --version
```

✅ 看到版本号 = 装好了。❌ 出现 `command not found` → 再重开一次终端；还不行，来找我。

### 6.3 第一次启动 + 登录

```bash
cd ~/code
kimi
```

1. 进入一个对话框界面后，输入 `/login`，回车
2. 选 **Kimi Code OAuth**，按提示在浏览器里登录你的 Kimi 账号
3. ⚠️ 需要 **Kimi 会员订阅**（或 API key）。**如果你现在没有会员，完全不影响学习**：网页版 Kimi 一样能用——把报错原样复制发给我，本章的"咒语"在网页版同样有效。先把本章当作"会员之后的第一件事"存着
4. 以后想用：`cd ~/code && kimi`；退出输入 `/exit`

### 6.4 铁律：三许三不许

| ✅ 许（教练用法） | ❌ 不许（代写用法） |
|---|---|
| 问报错是什么意思 | 让它帮你写 / 改 `.c` 文件 |
| 问概念（要求大白话+类比） | 让它替你完成练习、测验和项目 |
| 让它出题考你、批改你写的代码 | 自己没想就直接要完整答案 |

**口诀：先自己挣扎 15 分钟，再问；问提示，不要答案。**

### 6.5 四个复制即用的"咒语"（网页版同样适用）

**① 报错救援**

> 我是零基础学 C 语言的大一学生。这段代码编译报错：【粘贴报错全文】。请用大白话告诉我：错在哪一行、为什么错。**只给提示，不要给我改好的代码。**

**② 概念解释**

> 请用大白话解释【指针】，不超过 3 句话，再给我一个生活类比。我是零基础。

**③ 出题考我**

> 我刚学完 C 语言的【变量和输入输出】。请出 3 道小题，从易到难，先不要给答案，我做完发给你批改。

**④ 代码体检**（终端里最强的一招——它能直接读你的文件）

先 `cd` 到代码所在文件夹再启动 `kimi`，然后输入：

> 请看一下我这个文件夹里的代码，指出 3 个可以改进的地方。**只指出，不要修改我的文件。**

### 6.6 两个安全提醒

- 它要**改文件或执行命令前，会停下来等你同意**。新手规矩：看不懂它在干嘛，就回复"先别动，解释一下你要做什么"。
- 它的"视野" = 你启动它时所在的文件夹。想让它看代码，先 `cd` 到那个文件夹再启动。

### 6.7 加分项（可选，先别碰）

- VS Code 扩展商店里有官方 **Kimi Code** 扩展（认准 Moonshot 官方）。终端用熟之前不用装——记住本阶段唯一的敌人是"什么都想同时学"。
