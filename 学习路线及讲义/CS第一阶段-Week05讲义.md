## 第 2 章 函数定义与调用：打包，然后喊名字

### 2.1 是什么 + 逐字符拆解

**画面：点外卖。** 调用函数 = 下单：报菜名（函数名）、给备注（参数）、等外卖员把货送回来（返回值）。你不需要知道厨房怎么炒菜——**你只需要知道"喊什么名字、给什么料、拿回什么货"。**

```c
int add(int a, int b) {
    return a + b;
}
```

- `int`（开头的）= **带回什么规格的货**：这个函数干完活，交回一个 int。
- `add` = **名字**，以后喊它就喊这个。命名规矩和变量一样（小写、见名知意）。
- `(int a, int b)` = **进料口**：要干活，得塞给它两个 int。里面每个料都要写明规格。
- `{ ... }` = 函数体：它真正干的活。第一行末尾**不加分号**（和 if、for 一个家族）。
- `return a + b;` = **交货**：把结果送回调用它的人（第 3 章细讲）。

**调用（喊名字）：**

```c
int result = add(3, 5);   // 下单：给料 3 和 5，用 result 接货
```

### 2.2 铁规矩：本周函数一律写在 main 上面

电脑读代码从上往下，**喊名字之前，它必须先见过这个名字**。所以本周的统一姿势：

```c
#include <stdio.h>

// 函数定义区：全部写在 main 上面

int main() {
    // 调用区：main 是"目录页"，几行调用，细节全在函数里
    return 0;
}
```

> 💡 **一句话认识即可**：函数想写在 main 下面也行，但要在上面先贴一行"预告"（函数声明）。本周用不上，❓悬念，以后细聊。

### 2.3 【动手】九九表函数版 `table_f.c`——复制粘贴的葬礼

痛点现场：如果让你把九九表**打印两遍**，一 main 到底的写法只能把整个双层循环复制粘贴一遍。函数版只需要喊两声名字。

手敲（主体是你 W04 的 `table99.c`，原样搬进函数里）：

```c
#include <stdio.h>

void print_table() {        // void = 这个函数不带回货，只干活
    for (int i = 1; i <= 9; i++) {
        for (int j = 1; j <= i; j++) {
            printf("%dx%d=%d\t", j, i, j * i);
        }
        printf("\n");
    }
}

int main() {
    print_table();          // 喊一声，打一遍
    printf("\n再来一遍\n\n");
    print_table();          // 再喊一声，又打一遍
    return 0;
}
```

```bash
gcc -Wall table_f.c -o table_f && ./table_f
```

✅ 验收：九九表完整打两遍，而循环代码**只写了一次**。

**逐行讲解**：`void print_table()` 里第一个 `void` 表示"不带回货"（只干活不交货）；`main` 里两行 `print_table()` 就是调用——注意**括号不能省**，`print_table` 只是名字，`print_table()` 才是"喊它干活"。你在 `table99.c` 注释里写过"内圈是不会累加的，我之前并不理解这一点"——现在它原样搬进函数，行为一字不差，**打包不改变内容，只改变组织方式**。

### 2.4 本节坑与预防针

| 症状 | 病因 | 解法 |
|---|---|---|
| 报错 `implicit declaration` | 函数写在 main 下面又没预告 | 本周统一写 main 上面 |
| 函数死活不执行 | 只写了名字没写括号 | 调用要带 `()`：`print_table()` |
| 编译报奇怪错误 | 函数定义第一行末尾多了 `;` | 和 if/for 一样，删分号 |
| 报错"函数里不能定义函数" | 把一个函数写进了另一个的 `{}` 里 | 函数并排写，互不包含 |

> 📒 生词：`函数定义` `函数调用` `参数` `void`

## 第 3 章 返回值：外卖员带回货

### 3.1 return 的两个作用（缺一不可）

```c
return a + b;
```

这一句干两件事：

1. **交货**：把 `a + b` 的结果送回调用处
2. **下班**：函数**立刻结束**，return 后面的代码一句都不跑

⚠️ **打印 ≠ 带回货**（新手最容易混的一对）：`printf` 是把东西**打在屏幕上给人看**；`return` 是把东西**交回调用处给程序接着用**。屏幕上看到的，程序手里并没有。下周做项目时这句话会救你。

### 3.2 【动手】`max2.c`：比较器 + 边界测试第一枪

```c
#include <stdio.h>

int max2(int a, int b) {
    if (a >= b) {
        return a;
    } else {
        return b;
    }
}

int main() {
    printf("max2(3, 7) = %d\n", max2(3, 7));
    printf("max2(9, 2) = %d\n", max2(9, 2));
    printf("max2(9, 9) = %d\n", max2(9, 9));    // 边界：相等归哪边？
    return 0;
}
```

```bash
gcc -Wall max2.c -o max2 && ./max2
```

✅ 验收：`7`、`9`、`9`。

**讲解**：两个 return 各守一条分支，谁先执行谁就交货下班。第三组数据是**边界**——相等时 `>=` 把货归给 a，写 `>` 则归给 b。这题两个写法结果都是 9，但**"边界上那个数归哪边"必须是你决定的，不是碰运气的**（你在 grade 的 0 分、menu 的 0 选项上翻过三次车，病根都是这个；6.1 节给你系统解法）。

### 3.3 本节坑与预防针

| 症状 | 病因 | 解法 |
|---|---|---|
| 调用函数拿到天文数字垃圾 | 返回类型不是 void 却忘写 return | 必须 return；`gcc -Wall` 会喊 |
| return 后面的代码不跑 | return = 交货 + 下班 | 要干的活放在 return 前面 |
| 屏幕打了值但变量拿不到 | 把 printf 当成了"带回" | 屏幕上看靠 printf，手里拿靠 return |

> 📒 生词：`返回值` `return`

## 第 4 章 值传递：为什么函数改不动你的变量

### 4.1 【动手·事故演习】`change.c`：一次注定失败的修改

```c
#include <stdio.h>

void change(int x) {
    x = 99;                            // 在函数里把 x 改成 99
    printf("函数里 x = %d\n", x);
}

int main() {
    int a = 10;
    change(a);                         // 想让 a 变成 99
    printf("main 里 a = %d\n", a);
    return 0;
}
```

```bash
gcc -Wall change.c -o change && ./change
```

✅ 验收：**函数里 `x = 99`，main 里 `a = 10`——改了，但没完全改。**

### 4.2 为什么？——函数拿到的是复印件

**画面：复印机。** 你调用 `change(a)` 时，电脑不是把 a 这个柜子本身交给函数，而是**复印了一份 a 的值**，塞进函数的进料口 x。函数在复印件上怎么涂鸦（x = 99），你的原件 a 都纹丝不动。

这个规矩叫**值传递**：**参数传递的是"值的拷贝"，不是变量本身。**

### 4.3 本节坑与预防针

| 症状 | 病因 | 解法 |
|---|---|---|
| 函数里改了参数，main 里纹丝不动 | 值传递：改的是复印件 | 要改原件 → 传门牌号（第 5 章，练习 4 实战） |
| 以为参数换个名字就能改原件 | 名字不重要，复印件的本质不变 | 同上，认命：复印件就是复印件 |
| 函数 return 了，main 里还是旧值 | 没接货：光喊了 `add(3, 5)` | 用变量接住：`int r = add(3, 5);` |

### 4.4 那 scanf 凭什么能改掉你的变量？！

想想 W02 你就背过的铁律：`scanf("%d", &age);`——变量前面必须加 `&`。

现在把两件事拼在一起：

- 函数改不动你的变量（值传递，复印件）
- scanf 却能把你输入的值**放进**你的 age 里

矛盾吗？不矛盾——因为 scanf 拿到的**不是 age 的值，是 `&age`**。你当年背的是"门牌号"，背对了；但你一直没见过门牌号长什么样、为什么它就能改原件。

**第 5 章，揭盖。**

> 📒 生词：`值传递`

## 第 5 章 & 的真相：指针初识（W02 欠账，今日清算）

### 5.1 门牌号现身：& 就是"取地址"

回到 W02 的画面：内存是一整面墙的储物柜。当时只讲了"柜子有标签（变量名）"，藏了另一半——**每个柜子还有门牌号（地址）**，系统分配，形如 `0x7ffe...` 的一长串十六进制。

`&` 这个符号的意思就是：**取这个柜子的门牌号。**

【动手】`addr.c`，亲眼看看你柜子的门牌号：

```c
#include <stdio.h>

int main() {
    int age = 20;
    printf("age 里的值: %d\n", age);
    printf("age 的门牌号: %p\n", (void *)&age);
    return 0;
}
```

```bash
gcc -Wall addr.c -o addr && ./addr
```

✅ 验收：第一行 `20`；第二行类似 `0x7ffca3b28e9c` 的长串——**每次跑可能不一样**（系统分配的），这很正常。（`%p` 是打印地址专用的占位符，照抄即可；前面 `(void *)` 是 `%p` 的固定搭档，本周照抄，原理 ❓悬念。）

### 5.2 指针变量：专门装门牌号的柜子 + 逐字符拆解

门牌号也能存进变量——这种"专门装地址"的变量叫**指针**：

```c
int age = 20;
int *p = &age;
```

第二行逐字符拆：

- `int` = 这个门牌号对应的柜子里装的是 int（规格说明，免得上门后认错柜子规格）
- `*` = 定义里的 `*` 读作"**指针**"：`p` 是一个指针变量
- `p` = 变量名，里面装的是**门牌号**，不是普通的数
- `= &age` = 把 age 的门牌号装进去

读法：**p 是一个指针，指向 age 这个柜子。**

### 5.3 * 的另一面：顺着门牌号上门

`*` 在定义里是"指针"；在使用里它是另一个动作——**解引用：顺着门牌号上门，摸到那个柜子里的东西**。

【动手】`deref.c`——上门看，再上门改：

```c
#include <stdio.h>

int main() {
    int age = 20;
    int *p = &age;

    printf("顺门牌号看一眼: %d\n", *p);   // 上门取值
    *p = 21;                              // 上门改值！
    printf("age 现在: %d\n", age);        // 原件真的变了
    return 0;
}
```

```bash
gcc -Wall deref.c -o deref && ./deref
```

✅ 验收：`20`、然后 `age 现在: 21`。**`*p = 21` 隔着 p 改掉了 age 本人**——这是函数改不动变量的解药：给复印件没用，**给门牌号，让对方上门改**。

### 5.4 揭盖时刻：scanf 为什么要 &（三周悬念，一句话闭环）

把第 4 章和本章拼起来：

> **scanf 要往你的变量里放东西，但值传递只给复印件，放不进去。所以你必须递上门牌号 `&age`——"照这个地址上门，把用户输入放进这个柜子"。**

你 W02 抄了三个星期的 `&age`，今天起不再是咒语，是你自己能讲清楚的道理。**这就是第 9 章验收题要你大白话复述的内容，先在心里过一遍。**

### 5.5 本周边界（够用就好，别贪）

本周只学指针的"够用版"：**`&` 取门牌号、指针变量装门牌号、`*` 顺门牌号上门**。够你理解 scanf、够你写练习 4。

指针运算、指针的指针、指针和数组的关系——全是后续周的悬念 ❓，遇到了别自己深挖，标记下来。

⚠️ **一条保命规矩：指针没指向任何柜子，就绝对不许上门。** 没指向的指针（野指针/空指针）里装的是垃圾地址，`*p` 一上门程序就崩（段错误）。你论文数据集里的 **04 号样本（CWE-476 空指针解引用，一跑就崩）就是这个东西的正式名字**——你的学习线和论文线在这里会师了。

### 5.6 本节坑与预防针

| 症状 | 病因 | 解法 |
|---|---|---|
| 程序直接崩（段错误） | 指针没指向就 `*p` 上门 | 指针定义时先指向合法变量再上门 |
| 打了地址而不是值 |  printf 里少写了 `*`（打了 p 不是 *p） | p 是门牌号，`*p` 才是柜子里的东西 |
| 报错/行为诡异 | 对常量取地址（`&5`） | 门牌号只有柜子（变量）才有 |
| scanf 崩了 | 漏 `&`（W02 一级通缉犯） | 现在懂了：它要门牌号上门放东西 |

> 📒 生词：`指针` `地址` `解引用（*）`

### 6.2 "碰巧对 ≠ 对"：未初始化专项（你的翻车点 ×2）

**现场教学，用你自己的代码。** 你的 `score_avg.c` 最终版里有这么一行：

```c
int count,sum=0;
```

⚠️ 这行只初始化了 `sum`——**`count` 是垃圾值！** 后面 `count = count + 1` 是在垃圾上累加。你的程序之所以跑对了，是因为那块内存里**碰巧**是 0。换台电脑、换个编译选项、甚至代码挪几行，它就可能从 3 开始数，"共 4 门"秒变"共 7 门"。

> **垃圾值碰巧是 0，不等于你的代码是对的。碰巧对，是bug最阴险的形态——它让你以为自己对。**

规矩升级：**定义变量时全部初始化，一个不漏**——`int count = 0, sum = 0;`。编译器对这个坑有时喊有时不喊（要开优化选项才稳），所以**不能指望 gcc，只能靠"起手清零"的肌肉**。

顺手提一个你代码里的小字：`printf("...平均分%1f", ...)` 里的 `%1f` 是合法的，但它的意思是"最少占 1 位宽"，所以小数会拖 6 位尾巴；你想要的"保留 1 位小数"是 `%.1f`——**点号是关键**。

> 你论文数据集的 **07 号样本（CWE-457 未初始化变量）就是这个坑**——又在会师。学习线踩的每个坑，都是论文线的一个 CVE 原型。

### 6.3 main 应该是目录页

判断函数拆得好不好，看 main：**main 只剩几行调用、一眼能读完 = 拆对了**；main 里还塞着循环判断的细枝末节 = 还没拆完。一个函数只干一件事，名字说清楚它干啥。练习 3 的 BMI v3 你就按这个标准验收自己。

### 练习 1（跟做层）· 闰年函数版 `is_leap.c`（边界三问第一枪）

**要求**：把 W03 的闰年判断打包成函数 `int is_leap(int year)`——闰年返回 1，平年返回 0；main 里不调 scanf，直接打印 4 个测试用例。

**手把手**：

① 建文件：`touch is_leap.c`（内置终端里，或 VS Code【新建文件】）。

② 敲代码（判断条件和 W03 一字不差，只是搬进了函数）：

```c
#include <stdio.h>

int is_leap(int year) {
    if ((year % 4 == 0 && year % 100 != 0) || (year % 400 == 0)) {
        return 1;
    } else {
        return 0;
    }
}

int main() {
    printf("2024 → %d\n", is_leap(2024));
    printf("1900 → %d\n", is_leap(1900));
    printf("2000 → %d\n", is_leap(2000));
    printf("2026 → %d\n", is_leap(2026));
    return 0;
}
```

③ 编译运行：`gcc -Wall is_leap.c -o is_leap && ./is_leap`

✅ 验收：`1`、`0`、`1`、`0`。

**逐行讲解**：`2000` 就是你翻过车的那道边界——能被 100 整除但被 400 救回来。用边界三问复核一遍：① 整百年归哪边？（看 %100 和 %400 谁说了算）② 1999/2001 平年 ✅ ③ 特殊值——以后遇到"第 0 年"这类题再补。函数化的红利已经显现：**四个用例四行 printf，改函数重跑即得全部结果**，这在 main 里 scanf 的时代要来回输四遍。

### 练习 2（半独立层）· 幂函数 `power.c`（两个薄弱点一起练）

**要求**：写 `double power(double base, int n)`，返回 base 的 n 次方；main 里打印三组测试。

**💡 提示**：
- 这是 W04 累加器的乘法版——但**乘法罐子起手是 1，不是 0**（起手 0 的话，乘什么都归零）。想好再写，这是对"起手初始化"的变种考。
- n 个 base 连乘：循环 n 圈，每圈乘一次。

**自检数据**：`power(2, 10)` → `1024.00`；`power(5, 0)` → `1.00`（0 次方 = 1，循环一圈不跑——边界！）；`power(1.5, 3)` → `3.38`（`%.2f` 四舍五入）。

<details><summary>参考答案（做完再点开）</summary>

```c
#include <stdio.h>

double power(double base, int n) {
    double result = 1;              // 乘法罐子起手是 1！
    for (int i = 1; i <= n; i++) {
        result = result * base;
    }
    return result;
}

int main() {
    printf("power(2, 10) = %.2f\n", power(2, 10));
    printf("power(5, 0) = %.2f\n", power(5, 0));
    printf("power(1.5, 3) = %.2f\n", power(1.5, 3));
    return 0;
}
```

**讲解**：`result = 1` 是乘法世界的"清零"——写成 0 就全灭（6.2 的初始化肌肉，换个马甲再来一次）。`power(5, 0)` 循环条件 `1 <= 0` 一开始就不成立，一圈不跑直接交回 1——while/for"先验票后进场"的老知识自动给出了正确答案。**你没写任何 if，边界就对了——好代码的结构会替你挡 bug。**
</details>

### 练习 3（独立层）· 🏆 本周主项目：BMI 计算器 v3（函数版）

W03 埋的悬念今天收："分支里四条 printf 长得像？第 5 周学完函数，你会亲手把它收敛。"——就现在。

**要求**：把 W03 的 `bmi_v2.c` 拆成三个部分：

1. `double calc_bmi(double height, double weight)`——只算，返回 BMI
2. `void print_result(double bmi)`——只判断体型、打印结论（那四行 printf 的阶梯搬进来）
3. `main`——只负责 scanf 收身高体重、喊上面两个函数

**验收标准（两条都要）**：
- 输出和 v2 一模一样：四组自检数据 `22.6 标准 / 16.3 偏瘦 / 27.8 超重 / 34.6 肥胖` 全对
- main 不超过 8 行（不算花括号）——"main 是目录页"（6.3 标准）

**💡 提示**：`print_result` 里先 `printf("你的 BMI 是 %.1f，体型：", bmi);`（**不带 `\n`**），阶梯里各分支只打"偏瘦\n""标准\n"……四行 printf 就收敛成了一行前缀 + 四个词。

<details><summary>参考答案（做完再点开）</summary>

```c
#include <stdio.h>

double calc_bmi(double height, double weight) {
    return weight / (height * height);
}

void print_result(double bmi) {
    printf("你的 BMI 是 %.1f，体型：", bmi);
    if (bmi < 18.5) {
        printf("偏瘦\n");
    } else if (bmi < 24) {
        printf("标准\n");
    } else if (bmi < 28) {
        printf("超重\n");
    } else {
        printf("肥胖\n");
    }
}

int main() {
    double height, weight;
    printf("请输入身高(米): ");
    scanf("%lf", &height);
    printf("请输入体重(公斤): ");
    scanf("%lf", &weight);
    double bmi = calc_bmi(height, weight);
    print_result(bmi);
    return 0;
}
```

**讲解**：`calc_bmi` 一行 return 交货；`print_result` 用"前缀打一次 + 阶梯只打名词"收敛了 W03 的四条重复 printf——**重复收敛成一份，以后改格式只改一处**。main 瘦到 6 行：收、算、打，目录页。对比你的 v2 和这份 v3，功能一模一样，但 v3 每个零件能单独测试、单独替换——这就是函数的价值，也是 W08 毕业项目的组织方式。
</details>

### 练习 4（挑战层·可选）· 交换器 `swap.c`（指针的毕业礼）

**要求**：写 `void swap(int *a, int *b)`，交换两个变量；main 里 `int x = 3, y = 7;`，交换后打印 `7 3`。

**💡 提示**：
- 先跑一遍"复印件失败版"感受值传递：`void swap_bad(int a, int b)` 里用临时变量交换，main 里 x、y 纹丝不动——**亲眼确认失败，再写指针版**。
- 指针版：进料口收两个门牌号（`int *a`），函数里用 `*a`、`*b` 上门操作；调用时递门牌号：`swap(&x, &y);`。

**自检数据**：`3 7` → `7 3`；再试 `10 10`（相等的边界，交换后还是 `10 10`，不该崩）。

<details><summary>参考答案</summary>

```c
#include <stdio.h>

void swap_bad(int a, int b) {       // 复印件版：注定失败
    int temp = a;
    a = b;
    b = temp;
}

void swap(int *a, int *b) {         // 门牌号版
    int temp = *a;                  // 上门取 a 柜子里的值
    *a = *b;                        // 把 b 柜子里的值放进 a 柜子
    *b = temp;
}

int main() {
    int x = 3, y = 7;
    swap_bad(x, y);
    printf("失败版: %d %d\n", x, y);
    swap(&x, &y);
    printf("指针版: %d %d\n", x, y);
    return 0;
}
```

**讲解**：`失败版: 3 7`（复印件涂鸦，原件不动）、`指针版: 7 3`（上门真改）。`swap(&x, &y)` 和 `scanf("%d", &age)` 是**同一个动作**——递门牌号。scanf 是系统写好的 swap 亲戚，今天你自己写了一个。两个版本并排跑过一遍，值传递和指针就同时刻进脑子了。
</details>
